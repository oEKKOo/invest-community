# 《InvestHub 前端代码总结文档》

## 1. 前端整体定位
- 前端定位为投资社区系统的统一交互壳层，负责承载市场总览、行情浏览、社区讨论、投资组合展示、个人持仓、认证与管理后台等完整业务入口。
- 技术栈明确为 `Vue 3 + TypeScript + Vite + Pinia + Vue Router + Element Plus + Axios + ECharts + Lightweight Charts`。
- 前端主要承载的业务包括：
  - 用户登录/注册、认证、个人主页与隐私设置
  - 行情列表、个股详情、榜单、图表展示
  - 社区帖子流、帖子详情、评论、点赞、收藏、举报
  - 投资组合列表、详情、评论、收藏、点赞、收益曲线
  - 我的持仓、收益分析、持仓登记
  - 群组、私信、通知、管理员审核与风控页面
- 与后端关系：
  - 通过 `frontend/src/api/index.ts` 统一访问 `/api/*` REST 接口。
  - 路由守卫、登录态、刷新 Token 与后端 JWT 认证强绑定。
  - 行情、通知采用 SSE 流式更新，与后端推送协议耦合。
- 与数据库关系：
  - 前端不直接感知数据库，但页面结构、状态模型与后端实体高度对应，例如 `Post`、`Portfolio`、`UserHolding`、`Notification`、`Group`、`Report`。
- 与第三方库关系：
  - Element Plus 负责基础 UI 组件。
  - `vue-echarts` + `echarts/core` 负责首页、组合、持仓图表。
  - `lightweight-charts` 用于资产详情图表。
  - `dayjs` 负责日期格式化。
- 关联最紧密的模块：
  - `router/index.ts`
  - `stores/auth.ts`
  - `api/index.ts`
  - `components/layout/MainLayout.vue`
  - `views/Dashboard.vue`
  - `views/Community.vue`
  - `views/AssetDetail.vue`
  - `views/Profile.vue`

## 2. 前端功能总览
- 当前已实现的核心功能：
  - 认证：密码登录、短信登录、邮箱/手机号注册、验证码校验、OAuth 回调、实名认证、专业认证、风险评估。
  - 社区：帖子列表、发帖、草稿、板块筛选、评论、楼中楼、附件、投票、转发、收藏、举报。
  - 行情：资产搜索、行情列表、涨跌榜、个股详情、K 线、分时、资产相关内容聚合。
  - 投资组合：组合列表、创建、从持仓导入、组合详情、收益趋势、评论、更新日志、点赞、收藏。
  - 我的持仓：持仓录入、更新、删除、收益快照、累计收益曲线。
  - 个人主页：资料编辑、投资偏好、隐私设置、关注关系、点赞记录、收藏记录、成就。
  - 社交扩展：群组、入群审核、群邀请、私信。
  - 管理后台：内容审核、举报处理、用户治理、附件审核、板块管理、风险中心、分析中心、数据监控。
  - 公共能力：全局搜索、通知抽屉、SSE 推送、图表懒加载、预加载。
- 功能模块关系：
  - `认证 -> 路由守卫 -> 主布局 -> 各业务页面`
  - `社区/组合/持仓/行情` 共享用户身份、通知、搜索与举报能力。
  - `行情` 与 `社区/组合/持仓` 存在明显交叉，例如资产详情可快速发帖，组合和持仓都依赖资产行情。
  - `管理员功能` 与普通功能共用同一布局、同一 API 层、同一认证体系。
- 主流程模块：
  - 登录态与路由权限
  - 首页/行情/社区/组合/持仓
  - 帖子详情与资产详情
- 辅助模块：
  - 群组、私信、通知、认证子流程、管理子页面

## 3. 前端目录结构分析
### 3.1 核心目录清单

| 目录 | 职责 |
| --- | --- |
| `frontend/src/main.ts` | 应用入口，挂载 Pinia、Router、全局样式 |
| `frontend/src/App.vue` | 根组件，承载 `router-view` 与根级样式 |
| `frontend/src/views/` | 页面层，集中放置所有业务页面 |
| `frontend/src/components/` | 组件层，目前主要是布局组件、行情组件和举报弹窗 |
| `frontend/src/router/` | 路由定义、懒加载、全局前置守卫 |
| `frontend/src/stores/` | Pinia 状态管理，按业务域拆分 |
| `frontend/src/api/` | 请求封装与各业务接口模块 |
| `frontend/src/styles/` | 全局样式入口、设计 Token、Element Plus 覆盖 |
| `frontend/src/utils/` | 图表注册、预加载、空闲调度、消息提示、头像占位等基础设施 |
| `frontend/src/composables/` | 可复用组合式逻辑，目前主要是 `useQuoteStream.ts` |
| `frontend/src/types/` | 核心领域类型定义，统一前后端数据结构认知 |

- `views` 目录作用：
  - 直接对应路由页面。
  - 当前页面承担了大量展示、交互、数据请求和样式逻辑，是项目的主业务层。
- `components` 目录作用：
  - 当前拆分偏少。
  - 主要承担主布局、行情图表、资产选择、举报弹窗等通用块。
- `router` 目录作用：
  - 统一路由表、守卫、预加载入口。
- `stores` 目录作用：
  - 管理全局身份状态、行情缓存、帖子/组合详情与列表同步、通知、群组、私信。
- `api/service` 目录作用：
  - 用统一 Axios 实例封装所有接口。
  - 各模块路径与后端业务域一一对应。
- `styles/assets` 目录作用：
  - 项目无独立 `src/assets/`。
  - `styles` 实际承担设计系统、全局工具类与 Element Plus 主题改造。
- `utils/hooks/composables` 目录作用：
  - 主要解决懒加载、图表注册、SSE、格式化、通知、占位图等跨页面问题。

### 4.2 页面职责拆分
- `Dashboard.vue`
  - 负责首页聚合数据、市场榜单、图表懒加载、帖子/组合信息流、右侧统计。
  - 同时处理推荐流、关注流、排行切换、图表可见性观察器。
  - 职责偏重，已包含多个“子页面级”区块，适合继续拆成首页区块组件。
- `Community.vue`
  - 负责帖子列表、筛选、分页、发帖、板块拉取、附件上传、投票、举报。
  - 同时承担表单校验与内容类型切换。
  - 是典型的“展示 + 表单 + 数据 + 弹窗”全集中页面。
- `PostDetail.vue`
  - 负责帖子详情、楼中楼评论、评论附件、转发、投票、举报、分享。
  - 评论树与回复分页逻辑较重，建议继续拆分为评论列表/评论项/评论编辑器。
- `Profile.vue`
  - 负责展示用户信息、资料编辑、关注/粉丝、投资偏好、隐私设置、点赞/收藏抽屉、举报。
  - 还兼容“我的主页”和“他人主页”两种场景。
  - 页面职责非常重，是当前最需要拆分的页面之一。
- `Portfolios.vue`
  - 负责组合列表、筛选、创建组合、手动选资产、从持仓导入。
  - 同时承担收益格式化和组合卡片数据整形。
- `PortfolioDetail.vue`
  - 负责组合详情、收益图、饼图、组合评论、更新日志、举报。
  - 与 `MyHoldings.vue` 有数据心智上的联动，但逻辑未抽象复用。
- `MyHoldings.vue`
  - 负责持仓列表、收益快照、累计收益曲线、资产搜索、新增/编辑/删除持仓。
  - 同时承担大量格式化与表格计算逻辑。
- `AssetDetail.vue`
  - 负责资产基础信息、行情展示、图表懒加载、相关内容 lazy load、快速发帖、SSE 行情更新。
  - 页面实现质量较高，但仍集中了缓存、观察器、SSE、发帖等多种职责。
- 较轻页面：
  - `Search.vue`、`MarketList.vue`、`MarketRankings.vue`
  - `Groups.vue`、`GroupInvites.vue`、`GroupJoinRequests.vue`
  - `Messages.vue`
  - `auth/*` 页面
  - `admin/*` 子页

- 适合继续拆成子组件或 composables 的逻辑：
  - `Dashboard.vue` 的市场榜单、信息流、热门组合、热门标的、统计侧栏
  - `Community.vue` 的发帖弹窗、板块选择、附件上传、投票表单
  - `PostDetail.vue` 的评论树与回复编辑器
  - `Profile.vue` 的资料卡、成就卡、关注抽屉、隐私设置、投资偏好设置
  - `Portfolios.vue` 与 `MyHoldings.vue` 里的资产搜索/选择逻辑

### 4.3 页面交互流程
- 首页 `Dashboard`
  - 进入页面后：
    - 通过 `dashboardStore.fetchDashboardData()` 拉首页概览。
    - 通过 `marketStore.fetchRankings()` 拉精选榜单。
    - 根据 tab 通过 `getPosts()` 或 `getFollowingFeed()` 拉帖子流。
    - 通过 `portfoliosStore.fetchTopPortfolios()` 拉热门组合。
    - 管理员额外调用 `getAdminStats()`。
  - 用户切换榜单/Feed tab 时：
    - 触发新的接口请求或复用缓存。
  - 加载态：
    - 榜单、Feed、组合、图表均有局部 loading。
- 社区页 `Community`
  - 初始化：
    - 拉帖子列表 `postsStore.fetchPosts()`。
    - 拉板块树 `postsApi.getBoards()`。
  - 发帖：
    - 用户填写标题/正文/标签/资产/板块/内容类型。
    - 可上传附件。
    - 点击发布走 `PENDING_REVIEW`，点击存草稿走 `DRAFT`。
  - 切换状态或板块、翻页：
    - 重新拉列表。
  - 空状态：
    - 无数据时展示空列表。
- 帖子详情 `PostDetail`
  - 初始化：
    - 通过 `postsStore.fetchPost()` 拉详情。
    - 通过 `postsApi.getPostComments()` 拉顶级评论分页。
  - 交互：
    - 点赞/收藏走 store。
    - 评论/回复/编辑/删除走 `postsApi`。
    - 投票、转发、附件上传、举报为页面内局部逻辑。
  - 成功后：
    - 直接更新本地 `comments` 或 `currentPost`。
- 资产详情 `AssetDetail`
  - 初始化：
    - 先拉 `/assets/:id/` 详情，若内嵌 quote 则直接展示。
    - 若缺 quote，再走 `marketStore.fetchQuote()`。
    - 视图空闲后建立 SSE。
    - 相关内容区进入视口后再请求 `getAssetContents()`。
  - 图表：
    - 区块进入视口后才异步渲染 K 线/分时组件。
  - 快速发帖：
    - 页面内动态导入 `createPost` 并默认绑定当前资产。
- 组合列表 `Portfolios`
  - 初始化：
    - 拉组合列表。
  - 创建组合：
    - 支持手动资产选择或从持仓导入。
    - 资产占比按金额自动计算。
  - 交互：
    - 点赞/收藏走 `portfoliosStore`。
- 组合详情 `PortfolioDetail`
  - 初始化：
    - `portfoliosStore.fetchPortfolio()`
    - `getPortfolioReturnsHistory()`
    - `getPortfolioComments()` + `getPortfolioUpdates()`
    - 若当前用户是 owner，再拉 `getHoldingPerformance()`。
  - 用户操作：
    - 点赞/收藏/评论/复制分享/举报。
- 我的持仓 `MyHoldings`
  - 初始化：
    - `getMyHoldings()`
    - `getHoldingPerformance()`
    - 空闲时 `getHoldingReturnsHistory()`
  - 新增/编辑：

## 6. 路由系统分析
### 6.1 路由配置
- 路由文件：`frontend/src/router/index.ts`
- 路由特点：
  - 全部页面都通过动态 `import()` 懒加载。
  - 顶层分为：
    - 公共路由：`/login`、`/auth/callback/:provider`
    - 主布局路由：`/` + `MainLayout`
  - 使用 `props: true` 传递 `:id`、`:assetId`、`:groupId` 等动态参数。
  - 未单独定义 404 路由。
  - 未单独写静态 `redirect`，跳转逻辑主要在 `beforeEach` 中处理。
- 路由预加载：
  - `meta.preload = 'assetDetailCharts'` 的页面会触发 `preloadAssetDetailCharts()`。
  - 当前生效页面：
    - `/market`
    - `/market/rankings`

### 6.2 路由守卫与权限控制
- 是否有全局守卫：
  - 有，`router.beforeEach(...)`
- 登录态校验逻辑：
  - `to.meta.requiresAuth !== false && !authStore.isLoggedIn` 时跳转 `/login`
- 管理员权限逻辑：
  - `to.meta.requiresAdmin && !authStore.isAdmin` 时跳回首页 `/`
- 已登录访问登录页：
  - 自动回首页
- 管理员页面：
  - `/admin`
  - `/admin/data-monitor`
  - `/admin/moderation-queue`
  - `/admin/user-risk`
  - `/admin/analytics`
- 未登录跳转逻辑：
  - 统一由路由守卫处理
- 路由层异常处理：
  - 当前仅做重定向，不做错误页承接
- 特殊点：
  - 父路由 `/` 默认 `requiresAuth: true`
  - 子路由 `AssetDetail` 显式设为 `requiresAuth: false`，因此成为公开资产页
- 风险点：
  - 没有 404/无权限独立页面
  - “公开页面” 依赖 `requiresAuth: false` 覆盖父级 meta，后续新增半公开页面时容易遗漏

  - 抽出页面通用格式化工具

## 8. API 与前后端交互分析
### 8.1 API 封装方式
- 请求库：`axios`
- 封装入口：`frontend/src/api/index.ts`
- 请求实例：
  - `baseURL = VITE_API_BASE_URL || '/api'`
  - 默认超时 `10000`
- 请求拦截器：
  - 自动从 `auth-token.ts` 取 access token
  - 注入 `Authorization: Bearer xxx`
- 响应拦截器：
  - 业务码 `code !== 0` 统一报错
  - `401` 触发 `refreshAccessToken()`，成功后自动重放请求
  - 刷新失败则清空本地认证并跳转 `/login`
- Token 携带方式：
  - 请求头 `Authorization`
  - SSE 通过 query string 携带 token
- 统一返回结构处理：
  - `request()` 直接返回 `response.data.data`
  - 这意味着所有上层 API 都默认后端响应格式为 `{ code, data }`
- 错误处理：
  - 通过 `utils/notify.ts` 动态加载 `ElMessage.error`

### 8.3 数据流转链路
- 登录态流：
  - `Login.vue` -> `authStore.loginWithPassword/loginWithSms/register*` -> `api/auth.ts` -> `api/index.ts` -> 返回 `access/refresh/user` -> `authStore.setAuth()` -> `localStorage` -> 路由守卫放行
- 首页数据流：
  - `Dashboard.vue` -> `dashboardStore.fetchDashboardData()` -> `api/dashboard.ts` -> `dashboardData` -> 图表/统计渲染
  - `Dashboard.vue` -> `marketStore.fetchRankings()` -> `api/market.ts` -> `rankingsCache` -> 榜单 UI
  - `Dashboard.vue` -> `getPosts()` / `getFollowingFeed()` -> `feedPosts` -> 信息流 UI
- 列表页数据流：
  - `Community.vue` -> `postsStore.fetchPosts(filteredParams)` -> `api/posts.ts` -> `postsStore.posts` -> 帖子列表
  - `MarketList.vue` -> `getAssetsWithQuote(params)` -> `assets` -> 列表渲染
  - `Portfolios.vue` -> `portfoliosStore.fetchPortfolios()` -> `api/portfolios.ts` -> `portfoliosStore.portfolios`
- 详情页数据流：
  - `PostDetail.vue` -> `postsStore.fetchPost(id)` -> `currentPost`
  - `PostDetail.vue` -> `postsApi.getPostComments(id)` -> `comments`
  - `AssetDetail.vue` -> `GET /assets/:id/` -> `asset` + `quote`
  - `AssetDetail.vue` -> `useQuoteStream()` -> SSE -> `marketStore.updateQuoteFromStream()` -> `quote`
  - `PortfolioDetail.vue` -> `fetchPortfolio + getPortfolioReturnsHistory + getPortfolioComments + getPortfolioUpdates`
- 表单提交流：
  - 发帖：`Community.vue` -> 表单校验 -> `postsStore.createPost()` -> `api/posts.ts` -> 成功后刷新列表
  - 评论：`PostDetail.vue` -> `postsApi.createComment()` -> 推入本地 `comments`
  - 组合创建：`Portfolios.vue` -> `portfoliosStore.createPortfolio()` -> 成功后 `unshift` 到列表
  - 持仓登记：`MyHoldings.vue` -> `upsertHolding/updateHolding` -> 刷新持仓与收益
- 用户信息流：
  - 自己主页：`Profile.vue` -> `authStore.fetchCurrentUser()` -> `displayUser`
  - 他人主页：`Profile.vue` -> 直接 `fetch('/api/users/:id/')` -> 手工映射字段 -> `displayUser`
- 权限/登录态流：
  - `router.beforeEach` 使用 `authStore.isLoggedIn`
  - 页面内细粒度判断使用 `authStore.isAdmin`、`authCapabilities`
- 通知流：
  - `MainLayout.vue` 打开通知抽屉 -> 动态导入 `api/notifications.ts` -> 获取列表
  - 建立 `EventSource` -> 收到消息直接覆盖 `notificationItems`
  - 标记已读/点击跳转后局部更新 UI
- 待确认：
  - 通知 store 是否计划替代布局内本地实现
  - 群组与私信是否会引入实时通信

## 11. 核心页面/组件代码说明
- `frontend/src/router/index.ts` 的 `beforeEach`
  - 关键原因：控制登录态、管理员权限、公开资产页例外和图表预加载。
  - 解决问题：统一入口控制，而不是每页重复判断。
  - 输入：目标路由 `to`
  - 输出：放行或重定向
  - 修改注意：新增公开页或管理员页必须显式写 `meta`。

- `frontend/src/api/index.ts` 的 Axios 实例与响应拦截器
  - 关键原因：决定全站请求契约。
  - 解决问题：统一 token 注入、统一 `{ code, data }` 解包、统一 401 刷新。
  - 输入：任意请求 config
  - 输出：业务层直接拿到 `data`
  - 修改注意：只要后端响应格式改动，这里和所有 API 模块都要同步。

- `frontend/src/stores/auth.ts` 的 `setAuth()` / `fetchCurrentUser()`
  - 关键原因：登录态唯一权威 store。
  - 解决问题：持久化登录态、角色识别、认证能力聚合。
  - 输入：登录响应或当前用户信息
  - 输出：`token`、`refreshToken`、`user`
  - 修改注意：与 `api/auth-token.ts` 使用相同本地存储键，不能只改一处。

- `frontend/src/components/layout/MainLayout.vue`
  - 关键原因：是全站 UI 壳层。
  - 解决问题：统一菜单、全局搜索、通知、用户操作。
  - 输入：`authStore`、搜索结果、通知列表
  - 输出：页面导航和全局 UI 状态
  - 修改注意：
    - 搜索建议与搜索页共享 `api/search.ts`
    - 通知当前未走 `stores/notifications.ts`
    - 页面过重，任何改动都可能影响所有业务页面。

- `frontend/src/views/AssetDetail.vue`
  - 关键原因：是性能与实时能力实现最完整的页面。
  - 解决问题：资产详情缓存、quote 复用、图表懒渲染、内容区 lazy load、SSE 行情推送。
  - 输入：`assetId`
  - 输出：资产详情、行情、相关内容、快速发帖 UI
  - 修改注意：
    - 页面同时依赖 `api/index.ts`、`marketStore`、`useQuoteStream`
    - 请求顺序被精心设计为“先详情后 quote，再 SSE”，不宜随意打乱。

- `frontend/src/stores/posts.ts`
  - 关键原因：列表与详情点赞/收藏状态一致性依赖它。
  - 解决问题：同一帖子在多个页面对象实例之间的状态同步。
  - 输入：`postId`
  - 输出：目标对象集合的 likes / favorite 状态同时更新
  - 修改注意：如果未来帖子数据源再增加一个列表来源，需要一起纳入 `collectPostTargets()`。

- `frontend/src/stores/portfolios.ts`
  - 关键原因：和帖子 store 一样，负责组合列表/详情/热门榜统一状态回写。
  - 修改注意：`topPortfolios`、`portfolios`、`currentPortfolio` 三份对象可能同时存在。

- `frontend/src/views/Profile.vue`
  - 关键原因：承载用户中心绝大部分复杂能力。
  - 解决问题：资料编辑、关注关系、隐私设置、投资偏好、点赞收藏抽屉、KYC 汇总。
  - 修改注意：
    - 当前存在直接 `fetch('/api/users/:id/')`，绕过统一 API 层。
    - 页面体量过大，拆分前修改容易引入副作用。

## 12. 当前实现特点总结
- 当前实现的优点：
  - 业务覆盖面完整，已经具备可演示、可联调、可继续扩展的前端骨架。
  - 路由、API、store 的模块划分总体清晰。
  - 首页、资产详情、持仓、组合等核心页面已有较强产品感。
  - 图表按需加载、SSE、缓存、空闲调度、预加载等性能意识较好。
  - 类型定义较全，基础数据模型清楚。
- 当前实现的不足：
  - 大页面过多，页面层承担了过多业务逻辑。
  - 组件化不足，复用粒度偏粗。
  - 存在多处 `@ts-nocheck`，类型约束被显著削弱。
  - 登录态、通知、个人资料存在“第二实现”或绕过统一封装的问题。
  - 样式风格在不同页面之间存在明显不一致。
- 可维护性评价：
  - 中等。
  - 模块边界已建立，但页面内部复杂度偏高，维护成本主要集中在页面层。
- 扩展性评价：
  - 中上。
  - 继续新增页面、接口、store 都不难，但如果不先做适度整理，复杂度会继续快速上升。
- 明显问题清单：
  - 组件重复与逻辑分散
  - 页面职责过重
  - 状态耦合
  - 登录与通知实现分叉
  - 样式系统落地不完全统一

- 可清理项：
  - `components/market/AssetChip.vue`
  - `components/market/QuoteMini.vue`
  - `components/market/QuoteTag.vue`
    - 当前在业务代码中未见实际使用链条。
  - `stores/notifications.ts`
    - 当前未见 `useNotificationsStore()` 调用。
  - `stores/adminAnalytics.ts`
  - `stores/adminModeration.ts`
    - 当前管理页直接调 `api/admin.ts`，未使用这两个 store。
  - `App.vue` 与 `styles/index.scss` 的重复 reset
  - 若确认不再采用深色后台方案，可重点复查 `AssetSelect.vue` 和 `admin/DataMonitor.vue` 的旧视觉残留

- 结构不合理点：
  - `MainLayout.vue` 同时承担布局、搜索、通知、SSE、跳转，职责过重。
  - `Profile.vue`、`Dashboard.vue`、`Community.vue`、`Portfolios.vue`、`PortfolioDetail.vue`、`MyHoldings.vue` 都偏“大而全”。
  - API 层之外仍有页面直接 `fetch`。
  - Store 已存在但页面未接入，说明架构意图与实际落地存在偏差。

## 13. 后续开发建议
- 继续新增页面时：
  - 先在 `router/index.ts` 增加路由
  - 再在 `views/` 新建页面
  - 如果存在共享区块，优先先补 `components/common` 或业务子组件
- 新增组件时：
  - 不建议继续堆到页面内部
  - 建议按业务域拆目录，如 `components/community/`、`components/profile/`、`components/portfolio/`
- 新增接口时：
  - 先在 `api/` 对应模块增加封装
  - 需要跨页共享时再放入 `store`
  - 不建议页面直接写 `fetch`
- 新增权限控制时：
  - 先补 `router meta`
  - 再补 `authStore` 的 capability 计算
  - 页面内再做细粒度按钮显隐
- UI 重构优先顺序：
  1. `styles/variables.scss`
  2. `styles/index.scss`
  3. `MainLayout.vue`
  4. 大页面公共卡片与列表项
  5. 认证页、群组页、管理子页的视觉统一
- 性能优化优先排查点：
  - 大页面首屏脚本体积
  - `Profile.vue`、`Dashboard.vue`、`Community.vue` 的拆分机会
  - 图表是否还有重复渲染
  - SSE 链路在切页和重复进入时是否有多实例风险
- 减少打包体积和冗余文件：
  - 先检查 `components/market/` 未使用组件
  - 检查未接入的 `stores/admin*.ts` 与 `stores/notifications.ts`
  - 检查大型页面是否可把重型区块改为异步组件
- 推荐修改顺序：
  1. 统一认证与通知实现
  2. 抽离公共组件和格式化工具
  3. 拆分 `Profile.vue`、`Dashboard.vue`、`Community.vue`
  4. 清理未使用组件/store
  5. 再继续新增功能
- 适合先重构再继续新增的地方：
  - 用户中心
  - 社区发帖与评论区
  - 资产选择组件
  - 主布局通知中心
