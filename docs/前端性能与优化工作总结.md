# InvestHub 前端性能与优化工作总结

> **文档用途**：汇总主站前端（`frontend/`）已落地的性能策略与优化迭代，便于毕业论文「系统实现 / 前端优化 / 非功能需求」等章节撰写，以及团队工作记录与后续迭代对照。  
> **适用范围**：Vue 3 + Vite + Element Plus 技术栈；不含 React 原型目录 `investhub-community/`。

---

## 1. 工程背景与目标

投资社区类系统首屏往往同时面临：**多路由页面代码体积**、**图表库（ECharts、Lightweight Charts）较重**、**列表与信息流接口并发**等问题。本项目在前端侧以「首屏可感知时间可控、按需加载、构建可分析」为目标，在本科毕设可维护范围内实施工程化优化。

## 3. 既有前端优化总结（基线能力）

以下能力在性能专项迭代之前已存在于代码库，构成前端「性能与非功能需求」的基线。

### 3.1 路由级懒加载

- 业务页面均通过动态 `import()` 注册，首屏仅加载当前路由对应 chunk 及公共布局，避免将 Dashboard、社区、组合、管理端、个股详情等**全部打入初始 JS**。
- 实现位置：`frontend/src/router/index.ts`。

### 3.2 重型图表与组件的异步加载

- **ECharts / vue-echarts**：通过 `frontend/src/utils/chart-loader.ts` 的 `createLazyChartComponent` 与分场景 `load*ChartComponent`，延迟加载图表组件并缓存 Promise，减少重复下载与重复注册。
- **ECharts 按需注册**：`frontend/src/utils/echarts.ts` 中按场景（Dashboard、组合列表、组合详情、持仓等）调用 `setup*Echarts`，仅注册当前页面所需图表类型与组件。
- **个股 K 线 / 分时**：`frontend/src/views/AssetDetail.vue` 使用 `defineAsyncComponent` 异步加载 `KlineChart`、`IntradayChart`。
- **布局内重型 UI**：`frontend/src/components/layout/MainLayout.vue` 对全局搜索下拉、通知抽屉等使用异步组件，避免首屏强制拉取完整交互包。

### 3.3 首页（Dashboard）数据与渲染分层

- **首屏优先**：`onMounted` 中优先请求概览与榜单等核心数据（如 `fetchDashboardData`、市场榜单）。
- **次要数据延后**：信息流、热门组合、热门标的、管理统计等通过 `requestIdleCallback` 等在浏览器空闲时拉取，降低与首屏 JSON 的竞争。
- **图表区域**：对市场走势 ECharts 使用 `IntersectionObserver`（及空闲调度）控制挂载时机，先骨架后图表，避免阻塞首屏绘制。

### 3.4 行情与图表相关接口策略（简述）

- 行情榜单、K 线、分时等在前端 store 层配合 **in-flight 去重**、**短 TTL 缓存**（具体参数以 `frontend/src/stores/market.ts` 等实现为准），减轻重复请求与后端压力。该部分偏「接口层优化」，与首屏体验相互支撑。

### 3.5 构建产物与分包策略

- **Vite `manualChunks`**（`frontend/vite.config.ts`）：将 `vue`/`vue-router`/`pinia`、`echarts`/`zrender`/`vue-echarts`、`lightweight-charts`、部分 Element Plus 重型依赖等拆为独立 chunk，避免单文件过大、利于长期缓存。
- **压缩插件**：`vite-plugin-compression` 在构建后生成 `.gz` / `.br` 旁路文件；生产环境需 Web 服务器正确返回压缩资源（见第 5 节）。
- **体积分析**：`npm run analyze` 生成 `dist/stats.html`（rollup-plugin-visualizer），用于对比迭代前后 chunk 体积。

### 3.6 列表与分页（基线）

- 社区帖子、投资组合列表、行情列表等普遍采用 **分页** 或有限 `pageSize`，避免一次性渲染超长列表（极端大数据场景下可再引入虚拟列表，见第 6 节）。

## 4. 性能专项迭代（本次工作总结）

以下条目对应一次集中的「首屏与带宽争用」优化，与扫描结论一致，并已落地到仓库。

### 4.1 路由 meta 预加载收窄

**问题**：路由守卫中对带 `meta.preload: 'assetDetailCharts'` 的路由会触发 `preloadAssetDetailCharts()`，在空闲时预取 **K 线组件、分时组件、Lightweight Charts** 等 chunk。该 meta 若挂在首页、社区、组合、搜索等过多路由上，即使用户暂不进入个股详情，仍可能与首页 ECharts、次要接口争用网络与主线程。

**处理**：

- 从 **Dashboard、搜索、社区、组合** 等路由上移除 `preload: 'assetDetailCharts'`。
- **仅保留**与行情强相关的路由（如行情列表、涨跌幅榜），使「进入行情页后再预热个股图表代码」更符合用户路径。
- 帖子内资产链接、行情列表行等处的 **悬停/点击预热**（`preloadAssetDetailCharts`）仍然保留，作为补充。

**实现文件**：`frontend/src/router/index.ts`。

### 4.2 预加载调度策略（`preload.ts`）

**思路**：避免与首帧绘制抢时间片。

**处理要点**：

- 预加载任务前增加 **`requestAnimationFrame`**，再进入 `requestIdleCallback`。
- 适当 **拉长** `requestIdleCallback` 的 `timeout`（相对原更保守），无 `requestIdleCallback` 的环境使用略延后的 `setTimeout` 作为降级。

**实现文件**：`frontend/src/utils/preload.ts`。

### 4.3 投资组合列表页：接口分层

**问题**：组合列表请求与「当前用户持仓收益」数据原先并行发起；后者仅用于 **登录用户**在卡片上展示基于真实持仓推算的收益，并非列表 JSON 的硬依赖。

**处理**：先 `await` 组合列表接口并驱动界面渲染，再在 **`requestIdleCallback`**（无则 `setTimeout(0)`）中请求持仓收益，降低与首屏列表响应的竞争。

**实现文件**：`frontend/src/views/Portfolios.vue`。

### 4.4 文档与构建快照

- **`frontend/README.md`**：更新首开性能要点、Nginx **预压缩静态文件（gzip_static 等）** 与在线压缩备选说明、**构建体积快照**日期与数据、`npm run analyze` 与 `dist/stats.html` 说明。
- **仓库内示例**：`docs/nginx-frontend.example.conf` 可与实际部署对照，说明与 `vite-plugin-compression` 产物的配合方式。

### 4.5 后续可选方向（未强制实现）

- **帖子详情评论**：若单帖评论量极大，可在后端支持的前提下做评论分页或前端虚拟列表。
- **社区信息流**：在实测有需求时再考虑无限滚动或虚拟列表，与 `pageSize` 策略一并评估。

## 5. 部署侧注意事项（与论文「部署」小节）

1. **仅构建出 `.gz/.br` 不等于线上自动变快**：必须配置 Nginx/CDN **返回**预压缩文件（如 `gzip_static on`；Brotli 需模块或 CDN 能力），或启用服务端在线压缩。
2. **缓存策略**：对带 hash 的 `js/css` 可设较长 `Cache-Control`，配合版本发布流程。
3. **HTTPS 与 HTTP/2**：生产环境建议启用，利于多 chunk 并行加载（具体以运维环境为准）。

## 6. 论文撰写可用表述（建议）

以下内容可直接改编后用于毕业论文「前端实现 / 系统优化 / 非功能需求」等小节（请按学校格式微调用语）。

**路由与代码分割**：系统采用 Vue Router 异步路由，将各业务页面拆分为独立 chunk，避免用户首次访问时加载全部页面脚本，降低首包体积与解析时间。

**图表与重型库按需加载**：对 ECharts、Lightweight Charts 及个股 K 线/分时组件采用动态 `import` 与异步组件封装，并结合路由与交互场景预取，在可接受的交互延迟内平衡首屏性能与详情页打开速度。

**请求与渲染时序**：首页等对首屏敏感页面将核心数据请求与次要模块（信息流、统计等）分离，次要模块在浏览器空闲时加载；投资组合列表将非阻塞的持仓收益请求延后至空闲回调，减轻与列表主接口的并发争用。

**构建优化**：通过 Vite 手动分包将框架、图表库与业务 chunk 分离，并启用构建期 gzip/brotli 资源生成；结合 Web 服务器静态压缩配置，提升传输效率。
