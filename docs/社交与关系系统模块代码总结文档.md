# 《社交与关系系统模块代码总结文档》

## 1. 模块定位
- 模块业务目标：承载用户关系（关注/粉丝）与关系驱动内容分发（关注流），并提供用户间会话沟通能力（当前是会话型群聊，不是独立群组域）。
- 在系统中的作用：连接用户系统、内容系统、组合系统、通知系统，形成“关注关系 -> 内容曝光 -> 互动通知”的闭环。
- 当前关联模块：
  - 用户系统：`background/accounts/*`（`User`、`UserFollow`、认证与权限）
  - 内容系统：`background/content/*`（帖子、评论、互动）
  - 组合系统：`background/portfolios/*`（关注组合流）
  - 通知系统：`background/notifications/*`（`follow.created` 等事件转通知）
  - 前端展示：`frontend/src/views/Profile.vue`、`frontend/src/views/Dashboard.vue`、`frontend/src/views/Messages.vue`
- 社交关系系统与其他系统关系：
  - 与内容系统：`/api/feed/following/` 基于 `UserFollow` + `Content` 生成关注帖子流。
  - 与通知系统：关注、点赞、评论、提及、审核事件通过 `notifications/events.py` 进入 `Notification`。
  - 与用户系统：关注关系、粉丝计数、登录态和角色校验都依赖 `accounts`。
  - 与权限系统：前端路由守卫 + 后端 `IsAuthenticated` / 角色判断双层控制。

## 2. 当前功能总览
- 已实现功能：
  - 关注与取关（用户主页按钮 + 后端关注关系写入）
  - 粉丝列表与关注列表（Profile 抽屉 + 后端列表接口）
  - 关注动态流（帖子流 + 组合流）
  - 关注推荐（后端接口已提供，前端主路径暂未显式消费）
  - 用户会话私信（支持多人会话，`is_group=True`）
- 未实现/待确认功能：
  - 特别关注（星标用户）：未发现模型/接口/前端入口（待确认）
  - 独立群组域（群组创建、入群审核、群权限、群资料）：未发现 `Group`/`GroupMember` 等独立建模（待确认）
  - 群内专属讨论（社区化群帖子）：未发现 `group_post` 类模型（待确认）
  - 群资料分享：仅有私信附件上传，不是独立群资料中心（待确认）
- 功能依赖关系：
  - 用户关系域：`UserFollow` -> `followers_count/following_count` -> Profile 显示与关注流查询
  - 内容联动域：`UserFollow` + `Content(status='PUBLISHED')` -> 关注帖子流
  - 组合联动域：`UserFollow` + `Portfolio(is_public=True)` -> 关注组合流
  - 通知联动域：`publish_event("follow.created")` -> `Notification(FOLLOW)`

建议拆分子模块结论：
- 关注与取关：已实现
- 粉丝与关注列表：已实现
- 特别关注（星标用户）：未实现（待确认）
- 关注动态推送：已实现“拉模式列表”，未见预写入 Feed 表
- 群组创建与管理：当前仅“会话创建”，不是完整群组管理
- 群组权限控制：未实现独立群权限模型
- 群成员管理：会话参与者静态维护，未见邀请/踢出/审核接口
- 群内讨论：仅会话消息
- 群资料分享：仅消息附件（图片）上传

## 3. 前端结构分析

### 3.1 页面 / 组件清单
- 主页面
  - `frontend/src/views/Profile.vue`
    - 负责他人主页关注/取关、粉丝/关注抽屉、取关操作。
    - 关键函数：`toggleFollow()`、`openFollowDrawer()`、`fetchFollowList()`、`handleUnfollow()`
  - `frontend/src/views/Dashboard.vue`
    - 负责“关注-帖子/关注-组合”动态流展示。
    - 关键函数：`fetchFeed()`、`onFeedTabChange()`
  - `frontend/src/views/Messages.vue`
    - 会话列表、消息面板、发送消息、上传图片附件。
- API 层
  - `frontend/src/api/users.ts`：关注关系与关注流接口封装
  - `frontend/src/api/messages.ts`：会话/消息/附件接口
  - `frontend/src/api/index.ts`：统一鉴权、401 刷新、错误提示
- Store 层
  - `frontend/src/stores/auth.ts`：登录态 + 本地存储
  - `frontend/src/stores/messages.ts`：会话与消息状态
  - `frontend/src/stores/notifications.ts`：通知列表/未读数（和关注事件联动）
- 布局与复用
  - `frontend/src/components/layout/MainLayout.vue`：登录菜单、通知中心、SSE 订阅入口

归属划分：
- 关注关系组件/页面：`Profile.vue`、`Dashboard.vue`、`api/users.ts`
- 群组/群内内容相关：`Messages.vue` + `messages store/api`（会话型）

### 3.2 前端路由配置
- 路由文件：`frontend/src/router/index.ts`
- 关键路由：
  - `'/profile'`（本人主页）
  - `'/users/:userId'`（他人主页，动态路由）
  - `'/messages'`（私信会话）
- 路由守卫：
  - `beforeEach` 中 `to.meta.requiresAuth !== false && !isLoggedIn -> /login`
  - `requiresAdmin && !isAdmin -> /`
  - 已登录访问 `/login` 会重定向首页
- 嵌套路由：使用 `MainLayout` 作为父路由，业务页为 children。
- 群组访问权限逻辑：
  - 当前无独立群路由（如 `/groups/:id`），因此“私密群/审核群前端路由拦截”未实现（待确认）。

### 3.3 前端状态管理
- 技术：Pinia + localStorage。
- 用户关系相关状态：
  - 局部状态（`Profile.vue`）：`isFollowing`、`followList`、`followDrawerType`
  - 全局认证状态（`auth store`）：`token`、`refreshToken`、`user`、`isLoggedIn`
- 群组相关状态（当前为会话域）：
  - 全局 `messages store`：`conversations`、`currentConversationId`、`messages`
- 状态分层：
  - 全局：认证、会话、通知
  - 局部：主页关注按钮态、抽屉加载态、取关中 ID 集
- 状态更新流程：
  - 关注后：`toggleFollow` 成功即本地翻转 `isFollowing` 并调整 `followers` 计数
  - 取关后：`handleUnfollow` 成功后从 `followList` 删除并减少 `following`
  - 会话发送消息后：`messages store.sendMessage` 本地 push 新消息
- 观察：
  - `toggleFollow()` 使用原生 `fetch`，`handleUnfollow()` 使用 `api/users.ts`，调用风格不统一，后续重构风险较高。

### 3.4 前端交互流程
- 用户进入他人主页后的关注/取关流程
  - 触发入口：`Profile.vue` 关注按钮
  - 校验：登录态校验（`!authStore.isLoggedIn` 直接 return）
  - 调用：`POST/DELETE /api/users/{id}/follow/`
  - 成功：切换按钮文案、更新粉丝数、提示 `ElMessage.success`
  - 失败：`ElMessage.error`
  - 乐观更新：半乐观（成功后本地直接改状态，不二次拉取）
  - loading/empty/error：无独立 loading，失败仅 toast
- 粉丝/关注列表流程
  - 入口：点击统计卡片“关注者/关注”
  - 调用：`GET /api/users/{id}/followers/` 或 `/following/`
  - 成功：映射字段后渲染抽屉列表
  - 失败：toast + 空列表
  - 状态：有 `followListLoading`、empty 显示
- 特别关注设置流程：未发现入口/API（待确认）
- 关注动态流流程
  - 入口：`Dashboard` 切 tab（`follow`/`followPortfolios`）
  - 调用：`getFollowingFeed` / `getFollowingPortfoliosFeed`
  - 成功：更新 `feedPosts` 或 `followPortfoliosFeed`
  - 失败：控制台错误，清空列表（用户提示较弱）
  - 状态：有 `feedLoading`、empty、未登录提示
- 用户创建群组流程（当前会话型）
  - 入口：需通过 `createConversation(participantIds,title?)`（前端当前页未提供显式创建 UI）
  - 调用：`POST /api/messages/conversations/`
  - 成功：返回会话对象加入列表（依赖 store 后续刷新）
  - 待确认：前端是否有其他隐藏入口
- 用户申请加入群组 / 管理员审核 / 群资料流程：未实现（待确认）
- 用户进入群组查看讨论与资料流程（会话域）
  - 入口：点击会话列表项
  - 调用：`GET /api/messages/conversations/{id}/messages/`
  - 上传资料：`POST /api/uploads/messages/`（仅图片）
  - 发送：`POST /api/messages/conversations/{id}/messages/`

## 4. 后端结构分析

### 4.1 后端核心文件清单
- 用户关系
  - `background/accounts/models.py`：`User`、`UserFollow`
  - `background/accounts/views.py`：`manage_follow`、`UserFollowersView`、`UserFollowingView`
  - `background/accounts/user_urls.py`：用户关系路由
  - `background/accounts/feed_urls.py`：关注流路由
  - `background/accounts/serializers.py`：`UserFollowSerializer`、`UserPublicSerializer`
- 群组/会话域（当前实现）
  - `background/messages/models.py`：`Conversation`、`ConversationParticipant`、`Message`、`MessageAttachment`
  - `background/messages/serializers.py`：会话/消息创建与读取序列化
  - `background/messages/views.py`：会话列表创建、消息读写、附件上传
  - `background/messages/urls.py`：消息相关路由
- 通知与审计联动
  - `background/notifications/events.py`：领域事件到通知落库
  - `background/notifications/models.py`：通知表
- 内容/互动关联
  - `background/content/models.py`：`Content`、`Like`、`Comment`、`Mention`、附件模型
  - `background/content/views.py`：评论/点赞时 `publish_event(...)`

职责归类：
- 用户关系：`accounts/*`
- 群组域：当前无独立 Group 域；只有 `messages/*` 会话模型
- 群组内容/资料/审核：未发现独立实现（待确认）

### 4.2 社交关系相关接口映射
- 关注用户
  - 方法/URL：`POST /api/users/{user_id}/follow/`
  - 参数：路径 `user_id`
  - 权限：`IsAuthenticated`
  - 处理：`accounts.views.manage_follow`
  - 作用：创建 `UserFollow`，更新双方计数，发布 `follow.created`
- 取消关注
  - 方法/URL：`DELETE /api/users/{user_id}/follow/`
  - 权限：`IsAuthenticated`
  - 处理：`manage_follow`
  - 作用：删除关系并回退计数
- 获取粉丝列表
  - 方法/URL：`GET /api/users/{user_id}/followers/`
  - 权限：`AllowAny`
  - 处理：`UserFollowersView`
  - 返回：`UserFollowSerializer[]`
- 获取关注列表
  - 方法/URL：`GET /api/users/{user_id}/following/`
  - 权限：`AllowAny`
  - 处理：`UserFollowingView`
- 获取关注帖子流
  - 方法/URL：`GET /api/feed/following/?page=&pageSize=`
  - 权限：`IsAuthenticated`
  - 处理：`following_feed`
  - 数据源：`UserFollow -> Content(status='PUBLISHED')`
- 获取关注组合流
  - 方法/URL：`GET /api/feed/following-portfolios/?page=&pageSize=`
  - 权限：`IsAuthenticated`
  - 处理：`following_portfolios_feed`
- 获取关注推荐
  - 方法/URL：`GET /api/feed/following/recommendations/?limit=`
  - 权限：`IsAuthenticated`
  - 处理：`following_recommendations`
- 查询是否已关注
  - 当前无独立布尔查询接口；通常由列表或主页关系推断（待确认）。
- 特别关注相关接口
  - 未发现（待确认）。
- 动态推送分页/游标机制
  - 当前是 page/pageSize 偏移分页，不是 cursor/timestamp 游标；也非预写入 feed 表。

### 4.3 群组功能相关接口映射
当前“群组功能”仅对应会话系统，非独立群组域：
- 创建会话（可多人）
  - `POST /api/messages/conversations/`
  - 参数：`participantIds[]`、`title?`
  - 权限：`IsAuthenticated`
  - 处理：`ConversationListCreateView.post` -> `ConversationCreateSerializer`
- 获取会话列表
  - `GET /api/messages/conversations/`
  - 权限：`IsAuthenticated`
- 获取会话消息
  - `GET /api/messages/conversations/{id}/messages/`
- 发送会话消息
  - `POST /api/messages/conversations/{id}/messages/`
  - 参数：`content`、`attachmentIds?`
- 标记已读
  - `POST /api/messages/{id}/read/`
- 上传消息附件
  - `POST /api/uploads/messages/`（仅图片后缀）

未发现（待确认）：
- 创建/编辑/解散群组（独立资源）
- 加群申请与审核、邀请成员、移除成员
- 设置管理员/转让群主
- 群帖子列表、群资料上传删除下载与权限校验

### 4.4 数据库与数据模型
- 用户关系核心表
  - `user`（`accounts.User`）
    - 关键字段：`followers_count`、`following_count`、`status`
  - `user_follow`（`accounts.UserFollow`）
    - 字段：`follower_id`、`followee_id`、`created_at`
    - 约束：`unique_together(follower, followee)`
- 会话域表（当前替代“群组”能力）
  - `message_conversation`：`is_group`、`title`、`created_by`、`last_message_at`
  - `message_conversation_participant`：会话成员关系，唯一约束 `(conversation,user)`
  - `message`：消息正文
  - `message_attachment`：消息附件
  - `message_read_log`：已读日志，唯一约束 `(message,user)`
- 内容联动表（作为关注流来源）
  - `content`、`comment`、`like`、`favorite`、`mention`
- 通知表
  - `notification`（通过事件创建）

关键说明：
- 关注关系唯一约束：已存在。
- 是否允许互相关注：允许（无冲突约束）。
- 软删除：`UserFollow` 未使用软删；直接 delete。
- 群角色建模：未发现 owner/admin/member 独立角色表（仅 `created_by` + participants）。
- 群资料与群讨论关联：未发现独立群资料模型，只有消息附件。
- 审核状态字段：会话域无入群审核状态字段。

### 4.5 后端业务流程
- 关注/取关内部逻辑（`manage_follow`）
  - 参数校验：禁止关注自己
  - DB 读写：`get_or_create` / `delete`
  - 权限：登录必需
  - 事务：`transaction.atomic()` 包裹关键写入
  - 通知：关注成功触发 `publish_event("follow.created")`
  - 异常：重复关注返回 409；未关注取关返回 404
- 特别关注设置逻辑：未实现（待确认）
- 关注动态生成逻辑
  - 运行时查询 `UserFollow` 再查 `Content`/`Portfolio`
  - 无预计算 feed 表、无缓存代码证据（待确认）
- 群组创建逻辑（会话创建）
  - `participantIds` 校验至少包含一个他人且用户有效
  - 自动判定 `is_group = len(participants)>1`
  - 批量写入参与者记录
- 加群申请与审核逻辑：未实现（待确认）
- 群权限校验逻辑（会话级）
  - `_get_conversation_for_user` 保证仅参与者可读写会话
  - `_user_is_muted_or_banned` 限制消息发送/附件上传
- 群内讨论发布逻辑（会话消息）
  - `content` 与 `attachmentIds` 不可同时为空
  - 发送成功后更新 `last_message_at`
- 群资料上传访问控制（会话附件）
  - 上传者必须登录且非禁言封禁
  - 仅允许图片扩展名
  - 附件先“无 message”上传，发送消息时绑定

## 5. 前后端联动流程
- 正常关注流程
  - 用户操作：主页点击“关注”
  - 前端：`Profile.toggleFollow()` 发 `POST /users/{id}/follow/`
  - 后端：`manage_follow` 新建关系 + 更新计数 + 发事件
  - 返回：`code=0`
  - 前端更新：`isFollowing=true`，粉丝数 +1，toast 成功
- 取消关注流程
  - 前端发 `DELETE /users/{id}/follow/`
  - 后端删除关系并回退计数
  - 前端更新按钮态、列表项与计数
- 设置特别关注流程：暂无接口（待确认）
- 获取关注动态流程
  - 前端切换 dashboard tab
  - `GET /feed/following/` 或 `/feed/following-portfolios/`
  - 后端分页查询并返回 `items/page/pageSize/total`
  - 前端渲染列表或 empty
- 创建群组流程（会话）
  - 前端构造 `participantIds/title`
  - 后端校验参与者并创建会话+成员
  - 前端刷新会话列表（依赖调用）
- 加入公开群 / 私密群申请 / 群主审核：未实现独立流程（待确认）
- 进入群组查看内容流程（会话）
  - 前端选会话 -> `GET messages`
  - 后端校验参与者后返回消息
- 群资料上传/分享流程（会话附件）
  - 前端先上传图片获 `attachmentId`
  - 发送消息携带 `attachmentIds`
  - 后端将附件与消息绑定并返回消息详情

异常与边界：
- 权限不足：后端统一 401/403 + message
- 参数错误：序列化校验失败 4001
- 重复提交：
  - 重复关注返回 4090
  - 会话消息“空文本+空附件”被拒绝
- 已关注/未关注取关：
  - 已关注再关注 -> 409
  - 未关注取关 -> 404
- 已在群内/已申请：
  - 会话域无“申请入群”概念（待确认）

## 6. 核心代码解释
- `background/accounts/views.py` / `manage_follow`
  - 关键性：关系写入、计数维护、通知触发都在此。
  - 解决问题：保证关注关系一致性和可观测性（事件）。
  - 注意点：计数字段与真实关系表可能漂移，后续建议补偿任务。
- `background/accounts/views.py` / `following_feed` 与 `following_portfolios_feed`
  - 关键性：关注动态链路入口。
  - 输入：`page/pageSize`；输出：统一分页结构。
  - 注意点：当前是运行时拉取，后续做大规模推荐流需改为异步聚合。
- `background/messages/serializers.py` / `ConversationCreateSerializer.create`
  - 关键性：定义“会话即群聊”的判定逻辑（`is_group`）。
  - 注意点：没有群角色与成员权限扩展点，后续改造成本高。
- `background/messages/views.py` / `_get_conversation_for_user`
  - 关键性：会话访问权限的核心防线。
  - 注意点：任何新增消息/附件/已读接口都应复用该校验模式。
- `background/notifications/events.py` / `_handle_follow_created`
  - 关键性：关注动作到通知系统的桥接层。
  - 注意点：当前同步分发；高并发下建议异步消息化。
- `frontend/src/views/Profile.vue` / `toggleFollow` + `fetchFollowList`
  - 关键性：用户关系主要交互入口。
  - 注意点：`fetch` 与 `api/users.ts` 混用，错误处理与拦截器能力不一致。

## 7. 依赖关系与影响范围
- 外部依赖：
  - 前端：`Element Plus`、Pinia、Axios
  - 后端：DRF、JWT、Django ORM
- 模块依赖图（核心）：
  - 关系变更：`accounts` -> `notifications.events`
  - 关注流：`accounts` -> `content`/`portfolios`
  - 会话：`messages` -> `accounts.User`
- 修改关注逻辑影响点：
  - `accounts/views.py`、`accounts/models.py`、`frontend/Profile.vue`、`frontend/api/users.ts`、通知事件处理
- 修改群权限逻辑影响点：
  - `messages/models.py`（需引入角色模型）、`messages/views.py` 校验函数、前端会话 UI/状态结构
- 修改动态推送逻辑影响点：
  - `accounts/views.py` feed 接口、`Dashboard.vue` tab 数据流、分页协议
- 高风险点：
  - `followers_count/following_count` 冗余计数字段
  - `Profile.vue` 的原生 fetch 调用
  - 缺失统一 service 层导致逻辑散落在 views 中

## 8. 当前实现特点总结
- 优点：
  - 关注主链路闭环完整（关系+计数+通知+关注流）
  - 会话系统具备基础多人通信能力
  - 前后端接口返回格式较统一（`code/data/message`）
- 不足：
  - “群组”尚未形成独立领域模型，难支持审核/权限/资料库等需求
  - 特别关注、群治理、群资料均缺失
  - 关注按钮调用链风格不统一（`fetch` vs axios 封装）
  - 关系、推送、权限逻辑分散于多个文件（`accounts/views.py` 过重）
  - 权限策略部分在前端、部分在后端，存在重复与遗漏风险
- 可维护性与扩展性：
  - 现阶段中等可维护，新增“群组能力”时需要结构性重构。
