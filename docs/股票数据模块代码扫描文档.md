# 股票数据模块代码扫描文档

> 扫描范围：`background/` 下与 **Tushare、A 股/港股行情导入、行情/K 线服务** 相关的后端代码。  
> 生成目的：为将当前实现系统化扩展并维护 **A 股 + 港股 + 美股** 全链路提供改造地图。  
> **重要说明**：仓库内 **美股** 以 **Finnhub** 为主（标的、K 线、实时报价）；**A 股** 以 **Tushare** 为主；**港股** 为 **混合**：**日 K / 标的清单**可走 Tushare（`hk_basic` / `hk_daily`），**单资产实时行情刷新**在 `tasks._fetch_quote_for_asset` / `quote_refresh` 中与美股一样走 **Finnhub**（需配置 `finnhub_symbol`）。下文仍按你的要求完整梳理 Tushare 调用与 A 股耦合点。

---

## 1. 总览结论

* **当前是否使用 Tushare**：是。通过依赖包 `tushare`，`ts.pro_api(token)` 进程内懒初始化单例（`_get_pro_api`），调用 `pro.stock_basic`、`pro.daily`、`pro.hk_basic`、`pro.hk_daily` 等。**未使用** `pro_bar` / `ts.pro_bar`（全库检索无匹配）。
* **主要用于哪些数据**：
  * **A 股**：标的清单（`stock_basic`）、日线（`daily` 按 `ts_code` 或按 `trade_date` 全市场）、最新收盘快照（由日线推导）、全市场批量最新交易日行情（`get_latest_daily_quotes_all`）。
  * **港股（Tushare 部分）**：标的清单（`hk_basic`）、日线（`hk_daily` 单股或按 `trade_date` 全市场）。
* **数据导入方式概览**：
  * **手动 CLI**：`manage.py import_cn_stocks`（A 股列表 + 可选 K 线/行情）；`manage.py import_us_stocks`、`manage.py sync_market_data`（偏 Finnhub）。
  * **任务层**：`market_data/tasks.py` — `cn_symbols_sync`、`hk_symbols_sync`、`kline_sync`、`quote_refresh`、`quote_refresh_popular` 等。
  * **管理 API**：`POST /api/market/jobs/trigger/`（`market_data/views.py`）触发上述任务。
* **当前是否明显耦合 A 股**：**服务层**上，`CN_MARKETS = {'SH','SZ','BJ'}`、`ts_code` 形态 `{6位}.{SH|SZ|BJ}`、`currency='CNY'`、分时接口对 A 股不拉分钟线等，均以 A 股为第一公民；但 **`Asset.market` 已支持 HK/US**，海外路径已分叉。
* **扩展到港股/美股的总体改造难度**：
  * **在现有「A/Tushare + 海外/Finnhub」架构上补全产品与校验**：**中偏低**（修文案、`dq_check`、CLI 前置条件、Dashboard 等）。
  * **若要求美股日 K/清单也走 Tushare**（或统一只用一个供应商）：**中高**（需新增 `us_daily` 等封装、权限与限流、路由与字段映射）。

## 2. Tushare 调用扫描

### 2.1 Token 与初始化

| 项目 | 说明 |
|------|------|
| **环境变量** | `TUSHARE_API_TOKEN`（`tushare_service._get_api_token`），禁止写入日志 |
| **初始化** | `tushare_service._get_pro_api()`：`import tushare as ts` → `ts.pro_api(token)`，单例 `_pro_instance` |
| **配置探测** | `is_api_token_configured()`；`invest_backend/settings.py` 中 `TUSHARE_API_TOKEN_CONFIGURED`、`TUSHARE_QUOTE_CACHE_TTL`、`TUSHARE_REQUEST_DELAY` |

### 2.2 统一包装：`_call_with_retry`

* 包装各 `pro.*` 调用；成功返回后 `time.sleep(REQUEST_DELAY)`（默认 **0.4s**）；异常时根据错误串判断是否限流，限流则长等待（`RATE_LIMIT_WAIT * attempt`），否则指数退避（`BACKOFF_BASE ** attempt`），最多 **MAX_RETRIES=3** 次。

### 2.3 接口一览（按模块）

| 文件路径 | 函数/类 | 调用的 Tushare 接口 | 调用链路（摘要） | 用途 |
|----------|---------|---------------------|------------------|------|
| `market_data/tushare_service.py` | `get_stock_basic` | `pro.stock_basic(list_status=..., fields=...)` | `import_cn_stocks` / `tasks.cn_symbols_sync` | A 股基础列表 |
| 同上 | `get_daily_klines` | `pro.daily(ts_code=..., start_date=..., end_date=...)` | `get_latest_daily_quote`；`views.asset_kline` 库空回补 | 单股日 K 区间 |
| 同上 | `get_daily_klines_by_date` | `pro.daily(trade_date=...)` 全市场 A 股 | `kline_sync` A 股支路；`import_cn_stocks`；`get_latest_daily_quotes_all` | **按自然日一次拉全市场** |
| 同上 | `get_latest_daily_quotes_all` | 循环调用 `get_daily_klines_by_date` | `quote_refresh` A 股批量；`import_cn_stocks._refresh_quotes_for_assets` | 回退最近若干自然日直到有数据 |
| 同上 | `get_latest_daily_quote` | 间接 `get_daily_klines` | `tasks._fetch_quote_for_asset`（仅 **A 股**） | 单股最新收盘快照 |
| 同上 | `get_hk_basic` | `pro.hk_basic(list_status=...)` | `tasks.hk_symbols_sync` | 港股标的清单 |
| 同上 | `get_hk_daily_klines` | `pro.hk_daily(ts_code=..., start_date=..., end_date=...)` | `views.asset_kline` 港股库空回补 | 单股港股日 K |
| 同上 | `get_hk_daily_by_date` | `pro.hk_daily(trade_date=...)` | `kline_sync` 港股支路 | 按日全市场港股日线 |
| 同上 | `get_tushare_code` / `parse_tushare_code` | — | 与 `Asset.code`+`Asset.market`（SH/SZ/BJ）互转 | A 股内外码 |
| 同上 | `get_hk_tushare_code` / `parse_hk_ts_code` / `normalize_hk_listing_code` | — | 港股 `xxxx.HK` 与内部五位数字 code | 港股 ts_code |

**未使用**：`pro_bar`、`daily_basic` 等（以仓库当前检索为准）。

**关键常量**：`CN_MARKETS`、`HK_MARKET`、`MARKET_TO_SUFFIX`、`REQUEST_DELAY`、`RATE_LIMIT_WAIT`。

## 3. 数据导入扫描

### 3.1 导入入口

| 入口类型 | 文件 / 说明 |
|----------|-------------|
| Management Command | `market_data/management/commands/import_cn_stocks.py` — A 股：列表 → `Asset` → 可选按日全市场 K 线 / 全市场快照 |
| Management Command | `market_data/management/commands/import_us_stocks.py` — 美股：**Finnhub** `stock/symbol`，非 Tushare |
| Management Command | `market_data/management/commands/sync_market_data.py` — 通用同步入口（**注意**：非 `status` 任务**强制**要求 `FINNHUB_API_KEY`） |
| 任务函数 | `market_data/tasks.py`：`symbols_sync`（Finnhub）、`cn_symbols_sync`、`hk_symbols_sync`、`kline_sync`、`quote_refresh` 等 |
| REST | `market_data/views.py` `trigger_job` — 触发 `CN_SYMBOLS_SYNC`、`HK_SYMBOLS_SYNC`、`KLINE_SYNC`、`QUOTE_REFRESH` 等 |

### 3.2 全量 / 增量

* **标的（A 股）**：`get_stock_basic` 一次拉取（`list_status` 可配）；`update_or_create` 写入 `Asset`（`cn_symbols_sync` / `import_cn_stocks` 细节见代码注释：与历史 `market='CN'` 等数据合并）。
* **标的（港股）**：`hk_symbols_sync` → `get_hk_basic` → `update_or_create(code=..., market='HK', asset_type='STOCK', ...)`，`meta_json` 存 `tushare_ts_code` 等。
* **K 线（A 股 / 港股 Tushare 支路）**：从 `from_dt` **按日历日** 循环到 `today`，每个 `date_str` 分别调用 `get_daily_klines_by_date`（A 股）与 `get_hk_daily_by_date`（港股）；非交易日返回空则跳过。
* **K 线（美股等）**：`kline_sync` 中 `fh_qs` 走 `finnhub_service.get_candles` + `_write_klines`。
* **`force_refetch`**：`kline_sync` 在强制模式下先 `delete` 时间范围内已有日 K 再拉。

### 3.3 批量写入实现

* **K 线**：`AssetKline.objects.bulk_create(..., batch_size=BATCH_SIZE, ignore_conflicts=True)`，默认批量 **2000**（`tasks` 与 `import_cn_stocks`）；Finnhub 支路可用 `settings.KLINE_BULK_BATCH_SIZE` 覆盖 `_KLINE_BATCH_SIZE`。
* **行情快照**：A 股批量路径 `AssetQuoteSnapshot.objects.bulk_create`（约 2000/批）；海外为 **逐条** `create` + 缓存。
* **标的**：逐条 `update_or_create`（无 bulk）。

### 3.4 限流 / sleep / 重试 / 日志

* **Tushare 服务层**：见 §2.2；模块级常量可在 `tushare_service.py` 调整。
* **import_cn_stocks**：`--delay` 默认 **0.5s**，在成功拉到交易日数据后再 `sleep(max(0, delay - 0.4))`，避免与 `REQUEST_DELAY` 叠加过多。
* **quote_refresh（海外）**：`delay` 默认 **0.12s** 逐资产节流（Finnhub）。

### 3.5 导入性能与瓶颈

* **A 股日 K**：每交易日 **1 次** `daily(trade_date=...)`，优于早期「逐股 N 次」；总耗时 ≈ 交易日数量 ×（网络延迟 + 约 0.4s 保护等待）。
* **A 股行情批量**：`get_latest_daily_quotes_all` 最多尝试 **7** 个自然日找到有数据的交易日，再批量写快照。
* **瓶颈**：Tushare 积分/频次；`code → Asset` 映射在 A 股侧假设 **同市场 code 唯一**；港股映射使用 `normalize_hk_listing_code` 后的 key。

## 4. 数据库与模型扫描

### 4.1 相关表

| 表（Model） | 模块 | 作用 |
|-------------|------|------|

### 4.2 关键字段（多市场扩展）

* **`Asset.market`**：数据源路由的核心维度之一。
* **`Asset` 唯一约束**：`unique_together = (asset_type, code, market)`（见当前 `content/models.py`）。
* **`Asset.finnhub_symbol`**：**港股、美股** 在 `quote_refresh` / `get_or_refresh_quote` 的海外分支中依赖；A 股通常为空。
* **`Asset.currency`**：A 股同步常写 **CNY**；港股在 `hk_symbols_sync` 中取自 `curr_type`（默认 HKD）；美股来自 Finnhub。
* **`Asset.meta_json`**：存 Tushare 侧代码与扩展字段；若与旧文档 `docs/tushare_integration.md` 中「独立 `tushare_ts_code` 列」描述冲突，**以当前模型为准**。

### 4.3 表之间关系

* `Asset` 1:N `AssetQuoteSnapshot`、`AssetKline`；帖子、组合等通过 `asset_id` 关联。

### 4.4 哪些字段对多市场扩展最关键

* **`market` + `code`**：展示与路由；**`finnhub_symbol`**：海外实时行情与分钟 K；**`meta_json`（Tushare 侧 ts_code）**：在不增加列的情况下对接 Tushare 港股/A 股。

## 7. 扩展到港股/美股的改造建议

### 7.1 最小可行改造方案

* **维持双供应商现状**：A 股 + 港股日 K（Tushare）+ 港股/美股实时与分钟级（Finnhub）；补齐 HK 资产的 `finnhub_symbol` 与定时 `quote_refresh`。
* **工程修复**：统一错误文案；`dq_check` 增加 A 股/按 `market` 分支；`sync_market_data` 按任务类型决定是否强制 Finnhub。
* **可选**：为 `Asset` 增加显式字段 `tushare_ts_code`（减少 `meta_json` 歧义）。

### 7.2 推荐优先修改顺序

1. **一致性与排障**：`asset_quote` 404 文案；`get_or_refresh_quote` 文档字符串；`import_cn_stocks` 命令提示。
2. **数据质量**：`dq_check` 覆盖 A 股或分数据源。
3. **运维体验**：`sync_market_data` 与仅 Tushare 环境的兼容性。
4. **产品**：Dashboard 与分时能力预期（A 股）。

### 7.3 哪些可以复用，哪些需要重构

* **可复用**：`Asset`、`AssetKline`、`AssetQuoteSnapshot`；`kline_sync` / `quote_refresh` 骨架；组合收益逻辑。
* **需重构或增强**：`QuoteProvider`/`KlineProvider` 式抽象；`dq_check` 条件；若坚持港股报价也走 Tushare，需新增 **港股收盘快照** 批量路径并与现有 Finnhub 路径协调。

### 7.4 建议补充的抽象层

* **`MarketDataProvider`**：`(asset) -> quote / klines`，内部按 `market` 与配置分发 Tushare/Finnhub。
* **`ExchangeCalendar`（可选）**：交易日历，用于质检与调度。

## 8. 核心代码解释

### 8.1 `tushare_service._call_with_retry`

* **作用**：统一重试与节流，降低积分耗尽风险。
* **输入/输出**：传入 `pro` 的可调用对象与参数；返回 `DataFrame` 或 `None`。
* **修改注意**：成功即休眠 `REQUEST_DELAY`，按日批量同步时延迟会按调用次数累积。

### 8.2 `tasks.kline_sync`（Tushare 支路）

* **作用**：按自然日循环，分别拉 **A 股全市场**与**港股全市场**日 K，映射到本地 `Asset` 后 `bulk_create(..., ignore_conflicts=True)`。
* **依赖**：`TUSHARE_API_TOKEN`；`Asset` 已存在且 A 股 `market`∈CN，港股 `market=HK` 且 code 与 Tushare 对齐。
* **修改注意**：港股使用 `normalize_hk_listing_code` 后的 `hk_asset_map`。

### 8.3 `tasks.quote_refresh`

* **作用**：A 股用 `get_latest_daily_quotes_all` **批量**拉取并 `bulk_create` 快照；**非 A 股**（含 HK）逐个 Finnhub + `sleep(delay)`。
* **修改注意**：快照表会持续增长，需依赖 `cleanup_old_snapshots`。

### 8.4 `views.asset_kline`（库空回补）

* **作用**：无本地 K 线时，A 股调 `get_daily_klines`，港股调 `get_hk_daily_klines`，否则 Finnhub `get_candles`。
* **注意**：仅 **日 K** 对 A/HK 走 Tushare；更高频周期多走 Finnhub。
