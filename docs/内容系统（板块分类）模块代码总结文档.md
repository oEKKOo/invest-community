# 内容系统（板块分类）模块代码总结文档

> 适用范围：`frontend/`（Vue3 + Pinia）与 `background/`（Django + DRF）当前主干代码。  
> 结论先行：当前项目**尚未落地独立“板块分类”模型与管理能力**，现有“分类效果”主要由**资产关联（Asset）+ 标签（tags_json）+ 搜索/筛选参数**实现，属于“弱分类”方案。

---

## 1. 模块定位

### 1.1 业务目标（当前实现）

当前内容系统的核心目标是支持：

- 发帖、审核、展示、评论、点赞、收藏、举报；
- 按状态（发布/待审/草稿）与热度排序进行内容消费；
- 按资产（如某股票）聚合相关讨论内容。

### 1.2 在社区/投资系统中的作用

- 对用户侧：提供讨论流（`/community`）、帖子详情（`/posts/:id`）、资产详情下的相关讨论聚合（`/assets/:assetId`）。
- 对管理员：提供内容审核、举报处理、用户治理（`/admin`）。
- 对投资语义：通过 `Content` 与 `Asset` 多对多关系，把“内容”与“标的”连接。

### 1.3 与其他模块关系

- 与发帖模块：`ContentListView.create` 创建帖子并关联 `Asset`。
- 与内容筛选/搜索：`/api/posts/` 的 `status/tag/q/sort`；`/api/search/` 全局搜索。
- 与推荐/热度：`sort=hot` 基于 `like_count/comment_count`。
- 与后台管理：`/api/admin/posts/`、`/api/admin/posts/{id}/status/` 审核流。

## 2. 当前功能总览

### 2.1 已实现能力（和“板块分类”相关）

- **按资产聚合讨论**（可视作“市场讨论区”的一部分能力）：
  - `GET /api/assets/{id}/contents/`（新通用接口）
  - `GET /api/assets/{id}/posts/`（旧接口仍存在）
- **按标签筛选**：
  - `GET /api/posts/?tag=xxx`（后端 `tags_json__contains`）
- **按状态/热度筛选**：
  - `status`、`sort=new|hot`。

### 2.2 未实现/缺失能力（与你目标对照）

以下目前均未落地为真实“板块系统”：

- 市场讨论区（A股/港股/美股/期货）作为独立板块实体；
- 主题专区/公司研究专区/问答区的结构化板块；
- 板块 CRUD、排序、启用禁用、展示状态；
- 板块层级（一级/二级）；
- 板块图标/描述/封面/标签字段；
- 板块与帖子、权限、推荐位的显式关联；
- 后台板块管理页面与接口。

### 2.3 “市场讨论区/主题专区”等当前如何落地

- **市场维度**：依赖 `Asset.market`（SH/SZ/HK/US 等）+ 资产详情聚合内容实现，不是独立板块。
- **主题维度**：依赖发帖 `tags` 文本标签，未标准化（无标签字典表）。
- **公司研究/问答区**：无单独数据结构或页面，仅能通过标签/关键词弱表达。

### 2.4 板块与内容当前关联方式

- 不是 `Content -> Board`，而是：
  - `Content` 多对多关联 `Asset`（中间表 `content_asset`）；
  - `Content.tags_json` 存标签数组。

## 3. 前端结构分析

### 3.1 页面/组件清单（板块相关）

#### 主页面

- `frontend/src/views/Community.vue`  
  社区主列表页；含发帖弹窗、状态筛选、分页、点赞收藏、举报入口。
- `frontend/src/views/PostDetail.vue`  
  帖子详情页；评论楼层、回复、编辑/删除、评论点赞、举报。
- `frontend/src/views/AssetDetail.vue`  
  资产详情页；“相关讨论”聚合区（本质为资产维度内容聚合）。
- `frontend/src/views/AdminPanel.vue`  
  管理后台（审核/举报/治理）；**不含板块管理**。

#### API 与状态

- `frontend/src/api/posts.ts`：帖子/评论/收藏接口封装。
- `frontend/src/api/market.ts`：`getAssetContents()` 聚合内容。
- `frontend/src/stores/posts.ts`：帖子列表与详情状态。
- `frontend/src/types/index.ts`：`Post`、`Comment`、`Asset` 类型。

#### 通用组件

- `frontend/src/components/market/AssetSelect.vue`：发帖时关联资产选择器。
- `frontend/src/components/layout/MainLayout.vue`：主导航、全局搜索入口。

### 3.2 前端路由配置

核心文件：`frontend/src/router/index.ts`

- 板块列表页：当前无独立板块路由；社区页是 `/community`。
- 板块详情页：当前无独立板块详情；资产详情 `/assets/:assetId` 可视作“资产讨论聚合页”。
- 板块管理页：不存在；`/admin` 为内容审核治理，不是板块管理。
- 嵌套路由：`MainLayout` 下 children 路由。
- 路由守卫：
  - `requiresAuth !== false` 且未登录 -> `/login`
  - `requiresAdmin` 且 `!authStore.isAdmin` -> `/`
- 管理员校验逻辑：依赖 `authStore.isAdmin`（`ADMIN`/`MODERATOR` 均可）。

### 3.3 前端状态管理

- 使用 `Pinia`（`frontend/src/main.ts` + `stores/*`）。
- 与板块最相关的实际状态：
  - `postsStore.posts/currentPost/loading/pagination`
  - `Community.vue` 本地筛选状态：`activeFilter/currentPage/pageSize`
  - `AssetDetail.vue` 本地聚合状态：`relatedContents/contentSort/contentPage/contentTotal`
- 全局状态：`postsStore`、`authStore`。
- 局部状态：页面内表单、弹窗、筛选、分页、加载状态。

### 3.4 前端交互流程

#### 用户浏览内容

- 进入 `/community` -> `postsStore.fetchPosts()` -> 渲染帖子卡片。
- 切换“全部/已发布/待审核/草稿” -> 重算 query -> 再拉取。
- 点击帖子 -> `/posts/:id`。

#### 用户在“市场维度”切换

- 当前没有“板块 tab 切换”；
- 资产维度通过进入 `/assets/:assetId` 查看“相关讨论”。

#### 管理员新增/编辑/删除板块

- 当前**没有此功能**。

#### 表单校验/异常提示

- 发帖校验：标题必填+长度、内容必填+最小长度（Element Plus Form rules）。
- 删除确认：评论删除当前直接调用，无 `ElMessageBox.confirm` 二次确认（待优化）。
- 失败提示：`ElMessage.error`（如“发布失败”“加载失败”）。
- 成功反馈：`ElMessage.success`（如“帖子已提交审核”）。

## 4. 后端结构分析

### 4.1 后端核心文件清单

- 路由：
  - `background/content/urls.py`
  - `background/market_data/urls.py`
  - `background/invest_backend/urls.py`（总路由聚合）
- 视图：
  - `background/content/views.py`（帖子/评论/点赞/收藏/审核）
  - `background/market_data/views.py`（资产内容聚合等）
- 序列化器：
  - `background/content/serializers.py`
- 模型：
  - `background/content/models.py`（`Content/Asset/ContentAsset/Comment/Like/Favorite`）
- 权限：
  - DRF `AllowAny/IsAuthenticated` + 视图内 `request.user.role` 判断。

### 4.2 后端路由与接口映射（板块相关视角）

#### A. 当前“板块类”能力映射（实际为内容+资产聚合）

1) 获取“社区内容列表”

- 方法/URL：`GET /api/posts/`
- 参数：`status[]`、`authorId`、`tag`、`q`、`sort`、`page`、`pageSize`
- 返回：`items/page/pageSize/total`
- 权限：公开；未登录仅 `PUBLISHED`
- 处理：`ContentListView.get_queryset/list`
- 作用：全站内容流（非板块专属）

2) 获取帖子详情

- 方法/URL：`GET /api/posts/{id}/`
- 权限：未发布内容仅作者或管理员可见
- 处理：`content_detail`
- 作用：内容详情访问

3) 新增帖子

- 方法/URL：`POST /api/posts/`
- 参数：`title/content/tags/status/assetIds/assetCodes`
- 权限：登录且非禁言/封禁
- 处理：`ContentListView.create` + `ContentCreateSerializer.create`
- 作用：创建内容并可关联资产

4) 编辑帖子

- 方法/URL：`PATCH /api/posts/{id}/`
- 权限：作者或管理员
- 处理：`content_detail`（PATCH）
- 备注：资产字段更新逻辑中读的是 `asset_ids`，与前端 `assetIds` 命名存在不一致风险。

5) 删除帖子

- 方法/URL：`DELETE /api/posts/{id}/`
- 权限：作者或管理员
- 处理：`content_detail`（DELETE）
- 行为：软删除（状态改 `TAKEN_DOWN`）

6) 按资产聚合内容（最接近“板块聚合”）

- 新接口：`GET /api/assets/{id}/contents/` -> `market_data.views.asset_contents`
- 旧接口：`GET /api/assets/{id}/posts/` -> `content.views.asset_posts`
- 参数：`sort/page/pageSize`（新接口额外预留 `type`）
- 权限：公开，仅返回 `PUBLISHED`
- 作用：资产维度内容聚合

#### B. 板块 CRUD 接口现状

- 获取板块列表：**无**
- 获取板块详情：**无**
- 新增板块：**无**
- 编辑板块：**无**
- 删除板块：**无**
- 板块排序/启停：**无**
- 后台板块管理接口：**无**

### 4.3 数据库与数据模型

#### 当前涉及表

- `content`：帖子主体
- `asset`：标的实体
- `content_asset`：内容-资产关联
- `comment`：评论与回复
- `like`、`favorite`：互动关系

#### 关键字段

- `content.tags_json`：标签（JSON 数组）
- `content.status`：内容状态机
- `content.like_count/comment_count/view_count`：聚合统计
- `asset.market`：市场维度（SH/SZ/HK/US）
- `content_asset(content_id, asset_id)`：内容与资产绑定

#### 层级分类设计现状

- 不存在 `board/category` 表；
- 不存在 `parent_id` 板块层级；
- 仅 `comment.parent` 是评论层级，不是板块层级。

#### 板块与内容关系现状

- 关系缺失：没有 `content.board_id` 或 M2M `content_board`。

### 4.4 后端业务流程（现状）

- 请求进入 -> URL 映射 -> 视图函数/类 -> serializer 校验 -> ORM 读写 -> 统一 `{code,data,message}` 响应。
- 参数校验：
  - serializer 校验（状态、资产代码存在性、评论内容等）
  - 部分视图内手动校验（如评论编辑时间窗口、角色判断）
- 权限校验：
  - DRF 权限类 + `request.user.role` + 作者归属判断
- 异常处理：
  - 多数返回 `code=4001/4010/4030/4040/4090`
  - 前端拦截器与页面 `ElMessage` 共同反馈

## 5. 前后端联动流程

以下按“用户操作 -> 前端 -> 接口 -> 后端 -> 返回 -> 前端更新”。

### 5.1 浏览板块列表流程（当前替代：社区列表）

- 用户进 `/community`
- 前端 `Community.vue` 触发 `postsStore.fetchPosts(filteredParams)`
- 调用 `GET /api/posts/`
- 后端 `ContentListView.list` 过滤+分页
- 返回 `items/page/pageSize/total`
- 前端更新 `postsStore.posts/pagination`，渲染列表

异常/权限：

- 网络或服务异常 -> `ElMessage.error('获取帖子列表失败')`
- 未登录可看公开内容（`PUBLISHED`）

### 5.2 查看板块详情流程（当前替代：资产讨论聚合）

- 用户进 `/assets/:assetId`
- `AssetDetail.vue` 调 `get('/assets/{id}/')` + `getAssetContents('/assets/{id}/contents/')`
- 后端分别走 `asset_detail`（content app）与 `asset_contents`（market_data app）
- 返回资产信息与相关帖子列表
- 前端更新 `asset/relatedContents`

异常：

- 资产不存在 -> `el-empty 资产不存在`
- 聚合失败 -> 内容列表置空

### 5.3 按板块查看内容流程（当前替代：按资产/标签）

- 按资产：见 5.2。
- 按标签：社区页可传 `tag` 查询参数（后端支持）。

### 5.4 新增板块流程

- 当前**无实现**（无页面、无 API、无表）。

### 5.5 编辑板块流程

- 当前**无实现**。

### 5.6 删除板块流程

- 当前**无实现**。

### 5.7 权限不足/参数错误流程（已实现部分）

- 权限不足：后端返回 `4030`；前端全局或页面提示错误。
- 参数错误：后端 `4001` + `errors`；前端提示“请求失败/参数错误”。
- 未登录发帖评论：`4010`；前端提示“请先登录”。

## 6. 核心代码解释

### 6.1 `background/content/models.py` - `Content` / `ContentAsset`

- 关键性：定义“内容”和“资产关联”的核心结构，是当前“类板块能力”的底座。
- 解决问题：支持一篇帖子关联多个资产，实现资产维度聚合。
- 输入输出：ORM 层对象与关系查询。
- 依赖：`asset_posts` / `asset_contents` / 前端 `AssetDetail.vue`。
- 修改注意：
  - 若引入真实板块，应新增 `Board` 与 `Content` 关系，避免把 `Asset` 当板块。

### 6.2 `background/content/views.py` - `ContentListView.get_queryset`

- 关键性：统一处理内容列表权限和筛选。
- 解决问题：公开可见与作者/管理员可见边界。
- 输入：query params（`status/tag/q/sort`）
- 输出：分页列表
- 修改注意：
  - 当前 `status` 是 `getlist`，前端传单值也可；
  - 加板块筛选时建议新增 `boardId` 并建索引。

### 6.3 `background/market_data/views.py` - `asset_contents`

- 关键性：当前唯一“按维度聚合内容”的通用接口。
- 解决问题：资产详情页“相关讨论”。
- 输入：`asset id + sort/page/pageSize`
- 输出：`assetId/assetCode/assetName/items/...`
- 修改注意：
  - 与 `content.views.asset_posts` 功能重叠，建议统一。

### 6.4 `frontend/src/views/Community.vue` - 发帖弹窗与筛选流程

- 关键性：用户侧内容入口主页面。
- 解决问题：创建帖子、筛选状态、分页、点赞收藏。
- 输入：表单字段 `title/content/tagsInput/assetIds`
- 输出：调用 `postsStore.createPost/fetchPosts` 更新列表
- 修改注意：
  - 当前只支持“标签+资产”分类语义；
  - 引入板块后应增加 `boardId` 必填校验。

### 6.5 `frontend/src/stores/posts.ts` - `fetchPosts/createPost`

- 关键性：内容状态的全局流转中心。
- 解决问题：列表与详情状态集中管理。
- 修改注意：
  - 加板块过滤后，store 参数与缓存键要扩展，避免不同筛选互相覆盖。

## 7. 依赖关系与影响范围

### 7.1 板块分类（现状替代）依赖

- 资产模块：`Asset`、`/api/assets/*`
- 内容模块：`Content`、`tags_json`
- 前端社区页与资产详情页

### 7.2 依赖它的模块

- 发帖（资产关联）
- 资产详情页相关讨论
- 搜索模块（按关键字检索内容）
- 后台审核（不区分板块）

### 7.3 如果修改板块结构可能影响

- 前端：`Community.vue`、`PostDetail.vue`、`AssetDetail.vue`、`api/posts.ts`、`types/index.ts`、路由与后台页。
- 后端：`content/models.py`、`serializers.py`、`views.py`、`urls.py`、迁移脚本、索引策略。
- 数据：历史内容的板块回填与兼容策略。

### 7.4 最容易改坏的位置

- `ContentCreateSerializer` 字段映射（`assetIds/assetCodes`）；
- PATCH 更新资产关联时命名不一致（`asset_ids` vs `assetIds`）；
- 同类聚合接口双轨并存（`/posts/` vs `/contents/`）导致行为不一致。

## 8. 当前实现特点总结

### 8.1 优点

- 内容主链路完整：发帖 -> 审核 -> 展示 -> 互动；
- 权限模型清晰（游客/用户/管理员）；
- 资产聚合能力可用，投资场景契合。

### 8.2 不足

- 无独立板块实体，难以支持动态板块管理；
- 标签非标准化，主题治理和统计困难；
- 板块维度统计、推荐位、权限控制无法精细化。

### 8.3 可维护性/扩展性

- 中等：当前功能可维护，但对“板块系统”扩展支持弱。
- 主要问题：分类逻辑分散在 `tags + asset + 页面本地状态`，缺乏统一抽象。

### 8.4 设计不合理点（需单独指出）

- “板块分类”需求与当前“资产聚合/标签”实现存在架构错位；
- 板块作为核心业务实体未建模，后续任何板块能力都会落到大范围改造。

## 9. 后续扩展建议

### 9.1 新增板块字段（图标/描述/封面/排序/状态）

建议新增后端模型：

- `board` 表：`id/name/slug/type/icon/cover/description/tags_json/sort/status/is_visible/parent_id/...`
- `content.board_id`（或 `content_boards` 多对多，视是否允许多板块）

需改位置：

- 后端：`content/models.py`、`serializers.py`、`views.py`、`urls.py`、管理接口；
- 前端：`types/index.ts`、`api/posts.ts`、`Community.vue` 发帖表单与筛选 UI。

### 9.2 新增二级/多级板块

- `board.parent_id -> board.id` 自关联；
- 增加 `level/path/depth`（可选）；
- 查询优化：树结构接口 + 缓存。

### 9.3 新增板块管理员/权限/推荐位

- 权限表：`board_permission`（user/role -> board -> action）
- 推荐位：`board_recommendation_slot` 或 `content_recommendation`
- 管理端增加“板块管理”菜单与 CRUD 页面。

### 9.4 发帖必须选择板块

- 后端 `ContentCreateSerializer`：`boardId` 必填校验；
- 前端 `Community.vue`：增加板块选择器 + 表单必填；
- 发布前校验板块状态（启用/可见）。

### 9.5 板块统计（帖子数/浏览量/活跃度）

- 方案 A：实时聚合 SQL；
- 方案 B：异步统计表 `board_stats_daily`（推荐，扩展性更好）。

### 9.6 推荐改造顺序

1. 建模与迁移（Board + Content 关联）  
2. 新增只读接口（板块列表/详情）
