# 投资组合模块代码总结文档

> 更新时间：2026-03-27  
> 适用范围：`frontend/`（Vue3） + `background/`（Django/DRF）中与 Portfolio/Holding 相关代码  
> 目的：为后续扩展（收益曲线、回撤分析、调仓、复制组合、公开私密、榜单标签、互动增强）提供稳定的改造地图

---

## 1. 模块定位

投资组合模块当前承担两个层面的能力：

1. **社区内容化组合（Portfolio）**  
   用户创建“组合+资产权重”，可公开展示、点赞、评论、订阅、查看更新日志。
2. **个人真实持仓（UserHolding）**  
   用户维护自己的持仓数量和成本价，系统基于 `HoldingDailySnapshot` 计算收益，部分结果在组合页面用于“本人视角增强展示”。

整体设计是“**组合是策略表达**，**持仓是真实账本**”，二者通过 `assetId` 关联到统一资产表 `content.Asset`。

## 2. 当前功能总览

### 已实现

- 组合列表浏览、筛选、分页、创建（弹窗表单）
- 组合详情查看（资产配置、作者信息、风险标签、点赞、分享）
- 组合评论（支持父子评论结构字段，但前端当前只用基础发布）
- 组合订阅接口（后端已实现，前端未接入按钮）
- 组合更新日志展示（后端只读接口）
- 组合点赞（复用内容模块统一 Like）
- 组合公开/私密控制（创建与 PATCH 均支持）
- 持仓管理（增删改查）
- 持仓收益快照计算（当日收益、持有收益、累计收益）
- 持仓累计收益曲线（`/holdings/returns-history/`，已在“我的持仓”页面）

### 当前缺口

- 无独立“组合创建页/编辑页”，创建在列表页弹窗内
- 前端未提供组合编辑、组合删除入口（后端有 PATCH/DELETE）
- 组合详情无“收益曲线/回撤分析”图表（仅饼图 + owner 收益快照）
- 组合复制/模拟跟投未实现
- 组合公开私密切换入口不明显（仅创建时可选）
- 组合榜单维度较少（主要按 `returnsYTD` 或 likes）
- 组合评论未提供回复 UI（后端支持 `parentId/replyToUserId`）

## 4. 前端路由与守卫分析

路由定义：`frontend/src/router/index.ts`

- `/portfolios` -> `Portfolios`
- `/portfolios/:id` -> `PortfolioDetail`
- `/holdings` -> `MyHoldings`

权限守卫逻辑：

- 全局默认需要登录（父路由 `/` meta `requiresAuth: true`）
- 仅显式声明 `requiresAuth: false` 的页面可匿名访问
- 因此组合页面在当前前端路由下默认需要登录

与后端对比：

- 后端组合列表/详情是 `AllowAny`（且私有组合做额外校验）
- 即：**后端允许匿名看公开组合，前端路由目前阻断匿名访问**
- 这会影响“公开组合分享页”的真实外链可达性（需调整路由 meta 才能放开）

## 5. 状态存储与状态流转

### 5.1 投资组合状态

- 存储位置：`usePortfoliosStore`（Pinia 内存态）
- 无 localStorage 持久化
- 列表页进详情时通过路由参数再次请求详情，避免依赖上一页缓存

### 5.2 认证状态

- `frontend/src/stores/auth.ts`
- `token/refreshToken/user` 持久化在 localStorage：
  - `investhub_token`
  - `investhub_refresh_token`
  - `investhub_user`
- `frontend/src/api/index.ts` 请求拦截器从 localStorage 附带 Bearer Token

### 5.3 关键状态流转

1. 列表页加载 -> `fetchPortfolios(params)` -> 渲染卡片
2. 点击卡片 -> 跳转详情 -> `fetchPortfolio(id)` + 拉评论/更新日志
3. 创建组合（弹窗）-> `createPortfolio(payload)` -> 刷新列表
4. 点赞 -> `toggleLike` 乐观更新（失败回滚）
5. owner 视角收益 -> 调 `getHoldingPerformance()` 后按 `assetId` 映射组合资产

## 6. 后端结构分析

### 6.1 App 与路由

- App：`background/portfolios/`
- 聚合路由：`background/portfolios/urls.py`
- 全局挂载：`background/invest_backend/urls.py` -> `path('api/', include('portfolios.urls'))`

  - 组合主表（owner/title/description/risk_level/returns_ytd/is_public/like_count）

- 统一 camelCase 出参，兼容前端

- `PortfolioListView`：GET/POST
- `portfolio_detail`：GET/PATCH/DELETE
- `portfolio_top`
- `portfolio_comments`
- `portfolio_subscribe`
- `portfolio_updates`
- `UserHoldingListView` / `UserHoldingDetailView`
- `HoldingPerformanceView`

### 6.5 权限特点

- 组合接口大多 `AllowAny`，在函数内部判断 owner/role
- 写操作要求登录；非 owner 需 `MODERATOR/ADMIN`

## 8. 数据表与组合相关数据结构

### 8.1 组合主表 `portfolio`

核心字段：

- `id`
- `owner_id` -> 用户
- `title`
- `description`
- `risk_level` (`Low/Medium/High`)
- `returns_ytd` (Decimal, 4位小数)
- `is_public`
- `like_count`
- `created_at` / `updated_at`

索引：

- `(owner, -created_at)`
- `(is_public, -returns_ytd)`

### 8.2 组合资产表 `portfolio_asset`

核心字段：

- `portfolio_id`
- `asset_id`（FK 到 `content_asset`，可空以兼容旧数据）
- `symbol` / `name`（冗余字段）
- `allocation`（百分比）

约束：

- `unique_together (portfolio, asset)`

### 8.3 持仓与快照

- `user_holding`
  - `user_id + asset_id` 唯一
  - `quantity`, `cost_price`, `notes`
- `holding_daily_snapshot`
  - `holding_id + date` 唯一
  - `close_price`（来自 `asset_kline.close`）

### 8.4 互动与日志

- `portfolio_comment`（parent/reply_to_user 支持楼中楼）
- `portfolio_subscription`（订阅关系）
- `portfolio_update_log`（策略变更日志）

### 8.5 资产与点赞关联

- 资产来自 `content.Asset`
- 点赞记录来自 `content.Like`，`target_type='PORTFOLIO'`
- 点赞数反写 `portfolio.like_count`（在 `content/views.py` 统一更新）

## 9. 创建/编辑/删除/查看组合的完整流程

### 9.1 创建组合流程（当前主路径）

1. 用户在 `Portfolios.vue` 打开创建弹窗
2. 选资产：
   - 手动搜索资产 + 输入金额
   - 或从 `/holdings/` 导入持仓（`quantity*costPrice` 作为金额）
3. 前端把金额换算成 `allocation`（最后一项补齐 100%）
4. 调 `POST /portfolios/`
5. 后端 `PortfolioCreateSerializer` 校验并创建 `Portfolio + PortfolioAsset`
6. 若 `is_public=True`，写入关注动态 feed
7. 前端刷新列表

### 9.2 查看组合流程

1. 列表卡片点击跳 `/portfolios/:id`
2. 前端调 `GET /portfolios/{id}/`
3. 同步并行拉评论 + 更新日志
4. 若当前用户是 owner，再调 `/holdings/performance/`，按 `assetId`映射展示收益列

### 9.3 编辑组合流程（后端有、前端入口缺失）

1. 应调用 `PATCH /portfolios/{id}/`
2. 后端允许 owner 或管理员角色更新
3. 若传 `assets`，后端先删旧 `instance.assets` 再批量重建
4. 当前前端无 UI 挂载此流程（待补）

### 9.4 删除组合流程（后端有、前端入口缺失）

1. 应调用 `DELETE /portfolios/{id}/`
2. 后端 owner/管理员可删
3. 当前前端无删除按钮（待补）

## 10. 核心代码解释

### 10.1 前端“金额->仓位”换算

位置：`Portfolios.vue` `handleCreatePortfolio`

- 先累计总金额 `totalAmount`
- 每项 `allocation = amount/total * 100`
- 保留1位小数
- 最后一项用 `100-usedPct` 补齐，避免浮点和四舍五入误差

意义：保证提交后总仓位接近 100%，减少后端拒绝概率。

### 10.2 组合收益显示策略（当前是“owner收益增强”）

- 列表页 `getPortfolioReturn(portfolio)`
  - 仅当 `portfolio.userId === authStore.user.id` 才计算真实收益
  - 否则用 `portfolio.returnsYTD` 展示
- 详情页同样只对 owner 显示持仓市值/收益列

意义：公开组合不会暴露作者真实持仓收益细节，兼顾隐私和展示。

### 10.3 后端收益计算口径

`HoldingPerformanceView`：

- `marketValue = quantity * today_price`
- `costValue = quantity * cost_price`
- `unrealizedPnl = marketValue - costValue`
- `unrealizedReturn = unrealizedPnl / costValue`
- `dailyPnl = quantity * (today_price - yesterday_price)`
- `dailyReturn = dailyPnl / yesterday_value`

`HoldingReturnsHistoryView`：

- 按日期汇总所有持仓快照市值
- 与固定总成本比较得到累计收益率时间序列

### 10.4 点赞计数同步机制

- 点赞记录表在 `content.Like`
- `content/views.py` `_update_like_count()` 对 `PORTFOLIO` 分支更新 `portfolio.like_count`
- 组合序列化时输出 `likes` 与 `isLiked`

## 11. 修改风险点

1. **权限割裂风险（前后端不一致）**
   - 后端允许匿名看公开组合，前端路由默认拦截匿名。
2. **收益语义混淆**
   - `returnsYTD` 与 owner 实时持仓收益并存，口径不同，易造成误解。
3. **资产重建更新风险**
   - PATCH 带 `assets` 会全删全建，调仓历史无法保留。
4. **评论递归风险**
   - `PortfolioCommentSerializer` 递归序列化 replies，深层回复可能影响性能。
5. **N+1 查询风险**
   - `isLiked` 在列表序列化中逐条查询 Like，数据大时可能慢。
6. **持仓快照依赖任务**
   - 未执行 `fill_holding_snapshots` 时收益字段为空，前端体验下降。
7. **前端 `@ts-nocheck`**
   - 关键页面大量关闭 TS 校验，重构时容易引入隐性问题。

  - `POST /portfolios/{id}/clone/`

### 12.5 公开私密控制增强

建议新增：

- 前端详情页 owner 操作区加入公开/私密切换
- 后端加审计字段（`visibility_changed_at/by`）

### 12.6 组合榜单 / 风险标签

建议新增：

- 榜单维度：收益、回撤、稳定性、关注热度
- 风险标签：集中度、行业暴露、市场暴露

### 12.7 评论互动增强

- 前端回复 UI（`parentId/replyToUserId`）

## 附录：持仓收益计算口径（已并入）

以下为 `docs/holding_profit_calculation.md` 的核心口径合并摘要，用于统一组合与持仓文档中的收益定义。

### A. 收益定义

| 指标 | 公式 | 说明 |
|---|---|---|
| 当日收益（Daily PnL） | `Σ(quantity × (price_today - price_yesterday))` | 昨日估值到今日估值差值 |
| 当日收益率 | `daily_pnl / total_value_yesterday` | 以前一日总市值为基数 |
| 持有收益（Unrealized PnL） | `Σ(quantity × (price_today - avg_cost))` | 成本价到今日估值差值 |
| 持有收益率 | `unrealized_pnl / total_cost_value` | 以总持仓成本为基数 |
| 累计收益（MVP） | 等同持有收益 | 二期可拆分为已实现+未实现 |

### B. 数据落地对象

- 核心快照表：`holding_daily_snapshot`
- 关键约束：`(holding, date)` 唯一，避免重复快照
- 推荐路径：定时/命令补缺，接口侧读取轻聚合

### C. 与组合模块关系

- 组合是策略表达，持仓是用户真实账本；收益展示依赖持仓快照能力。
- `MyHoldings` 的收益曲线与组合扩展（如 owner 视角增强）可以复用同一收益口径。
